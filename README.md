## Engineering spectrum

<p align="center">
  <img src="./assets/engineering-spectrum.svg" width="100%" alt="Engineering spectrum"/>
</p>

<table>
<tr>
<td width="25%" valign="top"><b>Domain clarity</b><br/><sub>Different facts stay different. Estimate is not commitment; forecast is not baseline; unknown is not zero.</sub></td>
<td width="25%" valign="top"><b>Clear boundaries</b><br/><sub>Clients stay thin. Services own behaviour. Trust, data and runtime ownership are explicit.</sub></td>
<td width="25%" valign="top"><b>Boring operations</b><br/><sub>Health, migrations, backups, logs and failure modes should be visible and repeatable.</sub></td>
<td width="25%" valign="top"><b>Automation first</b><br/><sub>If the same boring work happens twice, it is probably trying to become code.</sub></td>
</tr>
</table>
